# Sample datasets

| File | Cases | Purpose |
|---|---|---|
| `sample.jsonl` | 6 | Smallest possible demo: exact, regex, contains/not_contains, a provider error, a flaky provider. |
| `mock-qa-suite.jsonl` | 44 | Realistic suite for the mock provider, built to exercise every UI state. |

`mock-qa-suite.jsonl` is generated by `build_mock_dataset.py` (edit the script, then `python datasets/build_mock_dataset.py`).

## What's in `mock-qa-suite.jsonl`
Categories (count): factual 10, math 5, classification 5, summarization 4, grounded 4, safety 3, format 5, code 2, reliability 6.
Each case's `metadata` scripts what the mock provider returns **per model**, e.g.
`"mock_output": {"mock-1": "Jupiter", "mock-2": "Saturn"}`, so one dataset simulates two models:

| Model | Role | Measured pass / fail / error (44 cases) |
|---|---|---|
| `mock-1` | baseline | 36 / 5 / 3 (81.8%) |
| `mock-2` | candidate | 34 / 8 / 2 (77.3%) |

Between them: **8 regressions** (e.g. hallucinated grounded answer, unsafe compliance with a phishing request, chatty JSON preamble) and **6 recoveries** (e.g. a fixed factual answer, `mock-1`'s over-refusal). These numbers were measured by running the domain engine over the file with retries enabled; they describe the scripted mock behaviour, not any real model.

Reliability cases cover: hard provider failure, timeout (retried then reported), flaky provider that recovers after 2 retries, rate limiting on one model only, slow responses (`mock_latency_ms` per model), and a provider that reports no token usage (renders as "—", not 0).

Use it: create a dataset in the UI, import `mock-qa-suite.jsonl`, then run it once with **mock-1** and once with **mock-2** (selector on the project page). Side-by-side comparison of those two runs is the next milestone.
